# 消息、详情互动与登录界面优化设计

## 目标

完善首页消息入口和未读提醒，修复帖子详情页点赞/收藏因远程刷新失效的问题，分离认领信息与评论区域，并将登录页调整为真实应用常见的登录优先信息架构。同时为点赞、收藏增加 MySQL 持久化，支持跨账号和跨设备使用。

## 范围与约束

- 保持现有 HarmonyOS ArkTS、Node.js、Express、Knex、MySQL 架构。
- 不引入新的大型依赖，不修改图片上传和存储服务。
- 点赞、收藏属于帖子互动数据；评论仍沿用当前客户端评论模型，本次只解决布局和交互冲突，不新增评论后端表。
- 消息已读状态本阶段保存在客户端会话中；通知数据仍由现有通知接口生成。
- 数据库变更提供独立 SQL 文件，并同步提供 Knex migration。

## 方案设计

### 1. 消息入口与未读角标

`UserTabs` 维护当前 Tab，`HomePage` 接收 `onOpenMessages` 和 `unreadCount`。首页右上角消息按钮点击后将 Tab 切换到消息页；当 `unreadCount > 0` 时，在图标右上角显示红色圆形数字角标。

进入消息 Tab 时调用 `AppStore.markAllNotificationsRead()`。`Index` 在远程刷新前收集已读通知 ID，并在重新加载通知后恢复这些 ID 的 `read` 状态，避免点赞、认领等操作触发刷新后角标重新出现。登录新账号或退出登录时清空本地已读 ID。

### 2. 点赞和收藏持久化

新增两张关系表：

- `post_likes(post_id, user_id, created_at)`，主键为 `(post_id, user_id)`；
- `post_favorites(post_id, user_id, created_at)`，主键为 `(post_id, user_id)`。

两张表均通过外键关联 `posts` 和 `users`，帖子删除时级联删除，用户删除时级联删除，并分别建立按 `user_id` 和 `post_id` 的查询索引。

服务端提供幂等接口：

- `PUT /api/v1/posts/:id/like`：创建点赞；
- `DELETE /api/v1/posts/:id/like`：取消点赞；
- `PUT /api/v1/posts/:id/favorite`：创建收藏；
- `DELETE /api/v1/posts/:id/favorite`：取消收藏。

列表和详情响应增加 `likeCount`、`isLiked`、`favoriteCount`、`isFavorite`。列表查询按当前用户批量加载互动状态，公开列表中的用户状态均为 false；详情查询按当前登录用户返回状态。重复创建和重复删除均保持幂等。

客户端在远程模式下调用上述接口，并直接更新当前详情对象，不能再调用会重新加载帖子列表的 `onChanged`；本地 Mock 模式继续使用 `AppStore` 现有方法。

### 3. 详情页布局

详情页按以下顺序展示独立卡片：图片、帖子状态与标题、点赞/收藏操作、认领/线索区域、评论区域。认领区域只在适用的帖子类型和用户身份下显示；评论输入和发送按钮放入单独的评论卡片，避免与认领申请内容共享布局空间。

远程详情加载现有 claims，并保留本地评论渲染；点赞或收藏请求失败时恢复原状态并显示错误信息。

### 4. 登录页信息架构

登录页不再把“登录/注册/找回密码”作为同级 Tab：

- 登录为默认主页面，标题和副标题下先显示账号输入框；
- 账号输入框下方显示“密码登录/验证码登录”切换；
- 根据登录方式显示密码或验证码输入及验证码按钮；
- 登录按钮和错误提示位于凭据区域之后；
- 底部使用“注册新账号”和“忘记密码”文字入口；
- 注册和找回密码页面提供“返回登录”。

注册三步流程、邮箱/手机号能力和现有认证接口保持不变。

## 错误处理

- 互动接口返回 404 时显示帖子不存在；409 或数据库约束错误转换为可读提示，不吞掉异常。
- 网络请求失败时恢复 UI 之前的点赞/收藏状态。
- 通知和登录界面沿用现有 `operationError`/`error` 展示机制。

## 验证标准

1. SQL 文件可在现有 `lostfound` 数据库上重复执行而不破坏已有数据。
2. 后端测试覆盖互动创建、重复创建幂等、取消和列表/详情状态字段。
3. ArkTS 编译成功。
4. 真机/模拟器验收：消息按钮可跳转、未读红色角标可出现并在进入消息页后消失；两个账号对同一帖子点赞/收藏状态互不串号；返回详情或重启 API 后状态仍保持；认领和评论区域不重叠；登录页面入口层级符合设计。
