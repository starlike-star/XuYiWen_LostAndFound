# 手机号与邮箱统一验证码登录设计

## 目标

登录页提供符合真实场景的统一验证码登录：用户输入已绑定手机号或学校邮箱，获取对应验证码后直接登录，不再要求或提示输入密码。项目仍使用本地演示验证码，不接入外部短信或邮件服务。

## 登录方式与界面

- 登录页提供“密码登录”和“验证码登录”两个入口。
- 密码登录支持手机号或学校邮箱，并显示密码输入框。
- 验证码登录支持手机号或学校邮箱，由输入内容自动识别目标类型，只显示六位验证码输入框。
- 两种登录方式分别保存账号和凭据状态；切换方式不会把密码误带入验证码输入框，也不会清空默认账号。
- 验证码登录默认填入学生演示手机号 `13800000001`；用户可以改为 `lin@campus.edu.cn` 验证邮箱流程。
- 演示账号说明同时列出学生手机号、学校邮箱与密码，避免把验证码误认为固定密码。

## 服务与数据流

1. 用户输入手机号或学校邮箱并点击“获取演示验证码”。
2. 服务先规范化目标：手机号去除首尾空格，邮箱去除首尾空格并转为小写。
3. 服务确认目标格式有效，并且存在绑定该手机号或邮箱的账号。
4. 对冻结或已注销账号不发放登录验证码，并返回对应状态提示。
5. 验证通过后，为规范化目标创建用途为 `LOGIN` 的验证码挑战，验证码五分钟有效、六十秒内不可重复发送。
6. 登录时按同一规范化规则查找账号，并校验验证码是否与该手机号或邮箱、`LOGIN` 用途匹配。
7. 验证码成功使用后立即失效；错误验证码、过期验证码、其他账号验证码均不能登录。

## 模型与兼容性

- 为登录方式增加统一验证码语义，避免用“手机验证码”表示同时支持手机号和邮箱的功能。
- 已持久化账号结构不变，现有默认账号已经绑定手机号和学校邮箱，不需要数据迁移。
- 保留密码摘要、会话持久化、冻结与注销校验逻辑。
- 不引入新依赖，不修改 SDK、构建配置或权限。

## 错误处理

- 空值或格式不合法：提示“请输入正确的手机号或学校邮箱”。
- 目标未绑定账号：提示“手机号或学校邮箱未注册”。
- 冻结账号：提示“账号已冻结”。
- 注销账号：提示“账号已注销”。
- 未获取、错误、过期或已使用验证码：沿用现有明确提示。
- 存储会话失败：沿用现有“数据保存失败，请稍后重试”，不得伪装为登录成功。

## 测试与验收

自动化测试覆盖：

- 默认学生手机号可以获取验证码并登录。
- 默认学生学校邮箱可以获取验证码并登录，邮箱大小写和首尾空格被规范化。
- 未注册目标不能获取登录验证码。
- 冻结或注销账号不能获取登录验证码。
- 手机号验证码不能用于邮箱，其他账号验证码也不能交叉使用。
- 验证码使用一次后失效。
- 原有手机号密码和学校邮箱密码登录保持可用。

手工验收覆盖：

- 切换到验证码登录后，页面只出现验证码字段，不出现密码标签、密码占位符或密码键盘。
- 默认手机号不被清空，获取的新验证码无需刷新即可显示。
- 输入验证码后点击一次登录即可进入应用，无需重启。
- 使用 `lin@campus.edu.cn` 重复上述流程可以进入同一默认学生账号。

## 非目标

- 不接入真实短信、邮件网关或图形验证码。
- 不增加第三方登录、扫码登录或多因素认证。
- 不改变注册、找回密码和绑定联系方式的业务流程。
