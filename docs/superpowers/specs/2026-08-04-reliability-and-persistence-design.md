# 失物招领应用可靠性与持久化修复设计

## 目标

在保留现有 ArkTS、ArkUI 和演示账号体系的前提下，完成以下修复：

- 保持已完成的首屏白屏修复：`Navigation` 只隐藏标题栏，不隐藏承载页面内容的 NavBar。
- 修正验证码计时、重复使用和联系方式规范化问题。
- 让账号及内容持久化失败可观测、可处理，不再静默假装成功。
- 按账号持久化帖子、评论、收藏、认领、线索和通知，并在应用重启后恢复。
- 修正消息已读、认领授权、演示发布者名称和关闭状态显示问题。
- 为启动失败和页面异步操作提供明确错误反馈。
- 建立自动化回归测试和可重复执行的 DevEco Studio 手工测试流程。

## 范围约束

- 沿用当前 Stage 模型、ArkTS、ArkUI、Preferences 和 Hypium，不新增第三方依赖。
- 不更换状态管理、构建系统、SDK 或路由架构。
- 内容数据按账号隔离保存，避免扩大为跨账号共享后端模型。
- 不实现服务器同步、数据库迁移、云服务、真实短信或邮件验证码。
- 不生成 HAP，不提交、不推送；当前目录不是 Git 仓库。

## 架构

### 认证状态

`MockAuthService` 保留测试用的固定时钟能力，但生产实例不再在构造时冻结时间。新增私有取时方法：存在测试时间时返回测试时间，否则每次调用 `Date.now()`。发送验证码、校验验证码、签发会话和写审计日志都通过该方法取时。

验证码目标统一规范化：去除首尾空白；包含 `@` 的目标再转为小写。发送和校验必须使用同一规范化函数。验证码校验成功后立即从 challenge 集合移除，后续再次使用返回“请先获取验证码”。

手机号和邮箱在 `AuthStore`、注册服务与绑定服务边界统一规范化，避免校验使用规范化值、保存或查重却使用原始值。

### 账号持久化

`AccountRepository` 继续保存账号和会话，但改变错误契约：

- Preferences 初始化失败：记录包含错误码和消息的 hilog，并向上抛出。
- JSON 读取或解析失败：记录 hilog，返回空数据，由启动流程决定使用演示初始值。
- 保存或 flush 失败：记录 hilog，并向上抛出，调用者不得显示成功。

`AuthStore` 的写操作捕获持久化错误并返回用户可见错误文案。初始化错误继续抛给根页面，由根页面显示启动失败状态。

### 内容持久化

新增 `ContentSnapshot`，包含：

- `posts`
- `comments`
- `claims`
- `clues`
- `notifications`
- `favoritePostIds`

新增 `ContentRepository`，复用 Preferences，使用账号 ID 派生内容键。Repository 只负责快照的读取、JSON 解析和写入，不承载业务规则。

`AppStore` 新增两个纯数据边界：

- `toSnapshot()`：返回与内部状态解耦的内容快照。
- `fromSnapshot(currentUserId, snapshot)`：从持久化数据创建 store。

首次登录且不存在快照时，使用 `createDemo(account.id, account.nickname)` 生成演示数据并立即保存。后续登录和应用重启从快照恢复。不同账号使用独立快照，保持现有演示应用的账号视角，不引入跨账号共享数据模型。

根页面负责内容生命周期：认证初始化完成后初始化内容 Repository、加载当前账号快照；业务操作成功后保存快照并刷新 `revision`。保存失败时保留内存状态，但显示“本次修改未保存”的错误，避免误导用户。

### 业务规则

- `markNotificationRead(notificationId)` 只修改存在且未读的通知，并返回是否发生变更。消息点击时先标记、保存和刷新，再打开关联帖子。
- `reviewClaim(operatorId, claimId, approved)` 必须确认认领记录存在、状态为待审核、关联帖子存在且 `post.ownerId === operatorId`。
- `confirmReturn(operatorId, claimId)` 必须满足同样的发布者所有权校验，并要求认领状态为已同意。
- `createDemo` 接收当前账号昵称，不再把当前账号拥有的演示帖子固定显示为“小林同学”。
- 详情页显式区分 `ACTIVE`、`CLAIMING`、`RESOLVED` 和 `CLOSED`，`CLOSED` 显示“已关闭”。

## 页面状态和错误处理

`Index` 增加启动错误状态。启动过程使用统一异步方法执行：

1. 获取 UIAbilityContext。
2. 初始化认证存储并恢复会话。
3. 若存在当前账号，初始化并加载对应内容。
4. 成功后设置 `ready = true`。
5. 失败时记录日志、设置错误文案，并展示可重试页面。

重试按钮清空错误并重新执行初始化。登录、注册、退出、资料修改、安全设置和内容保存的 Promise 均增加拒绝处理；页面只在存储操作成功时显示成功结果。

## 数据兼容性

- 账号 Preferences 名称和已有账号、会话键保持不变。
- 内容使用新键，不影响现有账号数据。
- 内容键不存在或解析失败时生成新的演示快照。
- 不自动删除损坏数据；日志记录失败，后续正常保存可覆盖对应单一内容键。
- 本次不增加版本迁移框架，因为此前没有内容持久化格式。

## 自动化测试

认证测试新增以下行为：

- 生产时钟路径不会固定使用构造时刻；测试固定时钟仍可推进。
- 60 秒后允许重新发送验证码。
- 5 分钟后验证码过期。
- 验证码成功使用一次后不可再次使用。
- 邮箱验证码目标忽略大小写和首尾空白。
- 手机号注册和绑定保存规范化后的值。

内容测试新增以下行为：

- `toSnapshot`/`fromSnapshot` 往返保留帖子、评论、收藏、认领、线索和通知。
- 修改恢复后的 store 不会意外修改原始快照对象。
- 消息首次标记已读返回 `true`，再次标记返回 `false`。
- 非发布者不能审核认领或确认归还。
- 发布者可以完成既有认领状态机。
- 演示帖使用传入的当前账号昵称。

Repository 的系统 Preferences 行为通过 ArkTS 编译和手工流程验证；纯快照转换与业务规则由本地 Hypium 单元测试覆盖。

## 手工验收流程

1. 冷启动应用，确认加载页后进入登录页，不再白屏。
2. 使用学生演示账号登录，发布一条信息、收藏一条信息、点击一条未读消息。
3. 完全关闭并重新启动应用，确认会话、发布、收藏和消息已读状态恢复。
4. 退出并登录另一演示账号，确认不会读取前一账号的内容快照。
5. 获取验证码后立即再次发送，确认提示等待；等待 60 秒后确认可以重发。
6. 使用验证码完成一次操作，再次使用同一验证码，确认被拒绝。
7. 使用带空格或大写字母的学校邮箱获取并校验验证码，确认规范化一致。
8. 以非发布者身份调用可达的认领操作，确认只能提交认领，不能审核或确认归还。
9. 制造 Preferences 不可用场景时，确认页面显示启动或保存失败信息，控制台有明确错误日志。

## 完成标准

- 新增回归测试先在旧实现上按预期失败，再在新实现上通过。
- 全部现有与新增 Hypium 单元测试通过。
- `default@CompileArkTS` 成功。
- CodeGraph 索引同步到修改后的调用关系。
- 未连接设备时不声称真机流程已通过；只提供待执行的手工步骤和风险说明。
